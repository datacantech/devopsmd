### **Что такое Git и его применение от простого к сложному**  

Git — это **распределённая система контроля версий (VCS)**, которая позволяет:  
- 📌 Фиксировать изменения в коде (коммиты).  
- 🔄 Синхронизировать работу команды (ветки, пул-реквесты).  
- ⏳ Откатываться к предыдущим версиям.  
- 🛠 Управлять проектами любого масштаба (от личных скриптов до enterprise-решений).  

---

## **1. Базовое применение (Личные проекты)**  
### **1.1. Установка и настройка**  
```bash
git config --global user.name "Ваше Имя"
git config --global user.email "ваша@почта.com"
```

### **1.2. Основные команды**  
| Команда | Описание |  
|---------|----------|  
| `git init` | Создать репозиторий в папке |  
| `git add файл` | Добавить файл в отслеживаемые |  
| `git commit -m "описание"` | Зафиксировать изменения |  
| `git status` | Показать текущие изменения |  
| `git log` | История коммитов |  

**Пример:**  
```bash
git init
git add script.py
git commit -m "Добавлен скрипт для анализа данных"
```

---

## **2. Работа с удалёнными репозиториями (GitHub/GitLab)**  
### **2.1. Клонирование и отправка кода**  
```bash
git clone https://github.com/username/repo.git  # Скачать репозиторий
git push origin main                          # Отправить изменения на сервер
git pull                                     # Обновить локальную версию
```

### **2.2. Ветки (Branches)**  
- **Создание и переключение**:  
  ```bash
  git branch feature/login   # Создать ветку
  git checkout feature/login # Переключиться на неё
  # Или одной командой:
  git checkout -b feature/login
  ```  
- **Слияние**:  
  ```bash
  git checkout main
  git merge feature/login
  ```

---

## **3. Командная разработка (Продвинутый уровень)**  
### **3.1. Pull Request (Merge Request)**  
1. Разработчик создаёт ветку:  
   ```bash
   git checkout -b fix/bug-123
   ```  
2. Пушит изменения:  
   ```bash
   git push origin fix/bug-123
   ```  
3. В GitHub/GitLab открывает **Pull Request** → код ревью → мердж в `main`.  

### **3.2. Разрешение конфликтов**  
Если два разработчика меняют один файл:  
1. Git покажет конфликт:  
   ```text
   <<<<<<< HEAD
   Ваша версия кода
   =======
   Их версия кода
   >>>>>>> branch-name
   ```  
2. Нужно вручную отредактировать файл и сделать:  
   ```bash
   git add файл
   git commit -m "Исправлен конфликт"
   ```

## **4. Профессиональные практики (DevOps/Enterprise)**  
### **4.1. Git Flow / Trunk-Based Development**  
- **Git Flow**:  
  - `main` — стабильная версия.  
  - `develop` — текущая разработка.  
  - Ветки `feature/`, `release/`, `hotfix/`.  
- **Trunk-Based**:  
  - Короткоживущие ветки → частые мерджи в `main`.  

### **4.2. Интеграция с CI/CD**  
Пример для гитлаба `.gitlab-ci.yml`:  
```yaml
stages:
  - test
  - deploy

unit_tests:
  stage: test
  script:
    - pytest

deploy_prod:
  stage: deploy
  only:
    - main  # Автодеплой только из main
  script:
    - ansible-playbook deploy.yml
```

### **4.3. Хуки (Git Hooks)**  
Скрипты для автоматизации:  
```bash
# .git/hooks/pre-commit
#!/bin/sh
flake8 .  # Проверка стиля кода перед коммитом для python
```

## **5. Специальные возможности**  
### **5.1. Интерактивный rebase**  
```bash
git rebase -i HEAD~3  # Объединить/переписать последние 3 коммита
```  
### **5.2. Stash**  
```bash
git stash          # Временно сохранить изменения
git stash pop      # Вернуть их
```  
### **5.3. Поиск по истории**  
```bash
git grep "TODO"    # Найти все TODO в проекте
git blame файл     # Кто и когда менял строку
```  

---

## **Итог**  
- 🔹 **Новичок**: Версионирование личных файлов.  
- 🔹 **Разработчик**: Ветки + пул-реквесты.  
- 🔹 **Команда**: CI/CD + код-ревью.  
- 🔹 **DevOps**: Автоматизация развёртывания через Git-хуки и пайплайны + ансибл фактура и терраформ + хельм.  

Git — это **стандарт** в разработке, и его глубинное понимание сильно ускоряет работу.
